Problem definition

Maze and Path-Finding Optimization

Input: a grid of R × C cells. Each cell is open, a wall, or mud (higher cost), plus a start cell S and an end cell E.
Output: a sequence of adjacent open cells from S to E, or a report that no path exists.
Constraints: moves go up, down, left or right only. Walls cannot be entered. Entering an open cell costs 1 and entering mud costs 5.
Objective: find the path with the minimum total cost while exploring as few cells as possible.

Grid input→Graph model→Algorithm→Path + metrics→Benchmark & compare

Graph model: every open cell is a vertex V, and every pair of neighbouring open cells is an edge E. Each cell has at most 4 neighbours, so E ≤ 4V and O(V + E) = O(V) on a grid.

  • Best case: the end is right next to the start, or (for DFS) the first branch tried leads straight to the end. For A*, a perfect heuristic expands only the cells on the path.
  • Worst case: the end is unreachable or is the last cell reached, so every open cell gets explored.
  • Dijkstra and A* here use a binary min-heap with lazy deletion. The heap can hold up to E entries, so each push or pop costs O(log E) = O(log V).
  • A* uses the Manhattan distance h = |r − rE| + |c − cE|. Every move costs at least 1, so h never overestimates (it is admissible) and A* stays optimal.
Algorithm 1

Breadth-First Search

BFS explores the grid in rings, all cells at distance 1, then distance 2, and so on, using a FIFO queue. The first time it reaches the end, that path has the fewest steps. It ignores mud cost, so on weighted grids its path can cost more than the optimum.

Data structure: queue
BFS(grid, S, E):
  queue ← [S]; visited[S] ← true
  while queue not empty:
    u ← queue.dequeue()
    if u = E: return buildPath(prev, E)
    for each open neighbour v of u:
      if not visited[v]:
        visited[v] ← true; prev[v] ← u
        queue.enqueue(v)
  return "no path"
Algorithm 2

Depth-First Search (Backtracking)

DFS follows one corridor as far as it goes and backtracks only at a dead end. It finds a path, often quickly in a perfect maze, but it can be much longer than the shortest one. Neighbours are tried in the order up, right, down, left.

Data structure: stack
DFS(grid, S, E):
  stack ← [(S, none)]
  while stack not empty:
    (u, p) ← stack.pop()
    if visited[u]: continue
    visited[u] ← true; prev[u] ← p
    if u = E: return buildPath(prev, E)
    for each open neighbour v of u:
      if not visited[v]: stack.push((v, u))
  return "no path"
Algorithm 3

Dijkstra's Algorithm

Dijkstra is a greedy algorithm: it always expands the unexplored cell with the smallest known cost from the start. Because costs are never negative, a cell's cost is final once it is removed from the heap. This gives the minimum-cost path even with mud.

Data structure: min-heap
DIJKSTRA(grid, S, E):
  dist[*] ← ∞; dist[S] ← 0
  heap.push(S, 0)
  while heap not empty:
    u ← heap.popMin()
    if done[u]: continue
    done[u] ← true
    if u = E: return buildPath(prev, E)
    for each open neighbour v of u:
      nd ← dist[u] + cost(v)
      if nd < dist[v]:
        dist[v] ← nd; prev[v] ← u
        heap.push(v, nd)
  return "no path"
Algorithm 4

A* Search

A* is Dijkstra with a sense of direction. It orders cells by f = g + h, where g is the cost so far and h is the Manhattan distance left to the end. Cells that lead away from the goal are expanded later or never. Ties go to the cell with the smaller h.

Data structure: min-heap
A_STAR(grid, S, E):
  g[*] ← ∞; g[S] ← 0
  heap.push(S, h(S))
  while heap not empty:
    u ← heap.popMin()          // smallest f = g + h
    if done[u]: continue
    done[u] ← true
    if u = E: return buildPath(prev, E)
    for each open neighbour v of u:
      ng ← g[u] + cost(v)
      if ng < g[v]:
        g[v] ← ng; prev[v] ← u
        heap.push(v, ng + h(v))
  return "no path"
Maze generation

Randomized depth-first maze generator

The grid starts as solid walls. The generator carves a passage from a random neighbouring cell two steps away and backtracks when it gets stuck, which produces a perfect maze with exactly one route between any two cells. The "with loops" layout then removes about 8% of the inner walls, creating alternative routes so the algorithms can return different paths. This step runs in O(V) time.
